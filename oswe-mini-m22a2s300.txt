## 🏗️ Greenfield design — key points
- **Service decomposition:** API Gateway → API Service (auth + idempotency) → Routing Engine (Dijkstra/Bellman-Ford/A*) → Graph Store → Workflow (Saga/Outbox) → External adapters (calendar, email). See `ARCHITECTURE.md`.  
- **Unified state machine:** single source-of-truth lifecycle for appointment states; events persisted and processed via outbox.  
- **Resiliency:** Idempotency keys persisted, retries with exponential backoff + jitter, call timeouts and per-dependency circuit-breakers, Saga compensation for multi-step flows.  
- **Algorithm strategy:** Validate inputs; if negatives exist:
  - Default: raise ValueError (guardrail), OR
  - If allowed: switch to Bellman-Ford (handles negative weights).  
- **Key API contract (example):** `POST /v2/appointments/schedule` (see `ARCHITECTURE.md`) — `request_id`, `idempotency_key`, `start_node`, `goal_node`, `allow_negative`.
