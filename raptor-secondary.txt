## 🏗️ Greenfield Architecture (Raptor Secondary)
- **Services**: `routing-service` (Bellman-Ford/Johnson’s, negative-weight-safe), `appointment-service` (state machine, idempotency, retries, breaker, saga/outbox), `audit-service`.
- **Data**: Postgres (`appointments`, `idempotency_keys`, `outbox_events`), Redis (idempotency cache, breaker stats), Kafka/SQS (outbox).
- **Resilience**: idempotency keys, exponential backoff retries, per-call timeouts, circuit breaker, transactional outbox + saga compensation.

```
Client/API GW <-> Appointment Svc <-> Routing Svc
                      |
                      v
                Outbox -> Kafka/SQS -> Notification/Audit
```

### Unified State Machine & Crash Points
| From → To       | Event              | Crash Points                                 |
|-----------------|--------------------|----------------------------------------------|
| INIT→VALIDATING | `validate_ok`      | schema errors                                |
| VALIDATING→ROUTING| `route_selected` | routing timeouts, negative cycles            |
| ROUTING→BOOKING | `provider_reserved`| booking errors/timeouts                      |
| BOOKING→CONFIRMED| `book_success`    | outbox publish failure                       |
| BOOKING→FAILED  | `book_failed`      | persistent booking failure                    |
| *→CANCELLED     | `cancel`           | compensation failures                        |
