## 🏗 4) New System Design (Greenfield replacement)

### Goals
- Safe routing: no silent mis-computations on negative edges.
- Idempotent scheduling API with idempotency keys.
- Retry/backoff + circuit breaker for downstream operations.
- Outbox/Saga-style compensation for external side-effects.
- Clear migration: shadow, dual-write, progressive cutover.

### Capability boundaries
- AppointmentService (orchestrator): scheduling, idempotency, attempt tracking, retries.
- RoutingService: compute path with algorithm selection (Dijkstra safe | Bellman-Ford).
- Delivery/Outbox workers: apply side-effects reliably.

### Behavior & state-machine (appointment lifecycle)
- init -> scheduled -> confirmed | failed | cancelled
- Attempt counts tracked; idempotency keys tied to scheduled state
- Retries update attempts; final failure emits compensation events to outbox

### Resiliency patterns
- Retry with backoff + jitter; configurable max attempts
- Circuit breaker to avoid sending to failing downstream
- Transactional outbox to persist side-effect intents and to ensure eventual delivery
- Idempotency keys to ensure safe repeated requests

### ASCII architecture
    [Client]
       |
    [API] -> [Appointment Service] -> [Routing Service]
                           |                  \
                       [Outbox] -> [Delivery Worker] -> [Downstream Systems]
 
### Key API payload example (Appointment)
{
  "id": "<uuid>",
  "idempotency_key": "<string, unique>",
  "payload": { "date": "2025-12-04T10:00Z", "type": "visit" },
  "status": "scheduled",
  "attempts": 0
}

Field constraints:
- idempotency_key: <= 256 chars, alphanumeric + -_ allowed
- payload: JSON object; sensitive keys are masked in logs
- status: enumerated among init|scheduled|confirmed|failed|cancelled
