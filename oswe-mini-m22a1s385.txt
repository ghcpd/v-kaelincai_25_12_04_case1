## 🔬 Integration tests (derived from crash points / risks)
Each test covers preconditions, steps, expected outcome, observability assertions.

1) Negative-edge validation
- Target issue: Dijkstra on negative weights
- Precondition: Graph with negative edge
- Steps: call shortest_path without allow_negative
- Expect: raise ValueError("negative weights")
- Observability: error logged with request id; test writes pass to results_post.json

2) Bellman-Ford path correctness
- Target issue: compute shortest path when negative allowed
- Precondition: Graph with negative edge
- Steps: shortest_path with allow_negative=True
- Expect: Correct path ["A","C","D","F","B"], cost≈1.0
- Observability: cost persisted in test results

3) Idempotency
- Target issue: multiple identical requests create duplicates
- Precondition: empty in-memory store
- Steps: send same request_id twice
- Expect: only one appointment stored
- Observability: appointment created once; request_id present in store

4) Retry/backoff & Outbox
- Target issue: transient notifier failures cause lost notifications
- Precondition: simulated notifier with high initial failure_rate
- Steps: create appointment with retry policy
- Expect: either notified or notification_failed after retries; outbox attempts tracked
- Observability: attempts, status, and delivered metric in results_post.json

5) Compensation / Reconciliation
- Target issue: downstream permanent failure and need to compensate/repair
- Precondition: notifier permanently failing
- Steps: create appointment (notification fails), then call compensate; then change notifier to healthy and deliver_outbox
- Expect: compensate removes appointment; reconciliation can deliver pending events when notifier healthy
- Observability: store state changes, outbox sent flag, events logged
